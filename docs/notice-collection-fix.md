# 유의사항 수집 안정화 (2026-10-26)

같은 문구가 오전·오후에 다르게 수집되던 원인에 맞춰 회사별 이벤트 영역을 지정했다.

- SK 7mobile: .noticeContainer의 유의사항을 접힘 상태와 무관하게 읽는다. 이미 열린 버튼을 다시 닫는 동작도 방어한다.
- U+ 유모바일: 공식 유의사항 섹션만 읽고 추천 이벤트·약관 팝업은 제외한다. 접이식·일반·중첩 양식을 지원한다.
- KTM: .attention-box의 각 패널을 읽는다. aria-expanded=true지만 실제 본문이 닫힌 경우에도 HTML 안의 전문을 읽으며, 일반 정의 목록 및 이벤트 이미지 대체설명을 지원한다.
- SKT 다이렉트: .event-detail-content 내부의 이벤트 조건을 읽는다. 개인화 할인 팝업 .noticeWrap은 제외한다. 일반 정의 목록과 이미지 대체설명을 지원한다.

문단과 금액을 중복 제거하지 않고 보관한다. 같은 문장이 다른 문단에 남아 있어도 삭제를 감지한다. 수집 범위가 바뀐 첫 비교는 조건 변경이 확정됐다는 표현 대신 수집값 교정이 포함될 수 있다고 표시하며 차이 자체는 남긴다.

수집 시도별 원문·영역·누락 문단·펼침 속성 및 시각을 보관하고, 같은 실행에서 완전한 값이 두 번 확인된 경우에만 비교 기준을 갱신한다. 부분 누락과 실제 금액 변경이 겹치면 후보를 보존하고 미확인으로 표시한다. 첫 수집이 불완전한 경우도 정상 기준으로 저장하지 않는다.

## 검증

- 회귀 테스트 100개 통과.
- 운영 저장본에 등록된 4개 회사 이벤트 131개를 격리된 headless Chrome으로 열어 검사했다.
- 저장한 실제 DOM에서 119개는 텍스트 유의사항을 추출했다: SKT 30/35, KTM 36/40, U+ 29/31, SK 7mobile 24/25.
- 나머지 12개는 지정 가능한 텍스트 조건을 확인하지 못하거나 외부 npay.sk7mobile.com 페이지다. 이를 변경 없음으로 확정하거나 다른 영역의 문구로 채우지 않고 미확인으로 남긴다. 이미지 속 문구의 OCR은 이 수정의 범위에 포함하지 않는다.
- 텍스트를 확인한 실제 DOM 119개의 문단을 모두 접힘/펼침 상태로 바꿔도 추출 결과가 같음을 확인했다.
- 접이식·일반·중첩·대체설명 양식을 포함한 실제 이벤트 14개는 최종 추출기로 두 번씩 다시 열어 전문이 일치하고 누락 문단이 없음을 확인했다.
- 이 검증은 당일 반복 수집 및 실제 DOM 재생이며 며칠간의 정기 운영 관찰을 대신하지 않는다.

## 재검증

`python -m unittest discover -s tests -v`

별도 Chrome과 설치된 Selenium으로 공개 이벤트를 읽는 검증(알림 전송 없음):

`python scripts/check_notice_browser.py work/notice-verification`

전체 이벤트 목록 JSON은 company/url/title을 가진 배열로 준비하고 다음처럼 검증할 수 있다.

`python scripts/audit_all_notice_regions.py work/audit-urls.json work/all-notice-audit`

검증 결과와 HTML은 전달한 작업 폴더에만 저장된다.
